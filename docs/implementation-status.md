# 首版实现与验收记录

验证日期：2026-10-13。开发分支：`dev`。本记录描述当前可运行首版及其证据，完整目标仍以架构与实施计划为准。

## 实现

应用保持 Rust 原生工程。FLTK 构建无图像解码组件，保留 Linux Pango；libarchive、zlib、liblzma、bzip2 静态链接。界面采用统一的深浅主题、系统字体、扁平控件、清晰的焦点和错误状态。来源树与日志 / 搜索 / 设置 / 副本标签页共同组成单窗口工作区。

当前已实现来源扫描和归档范围、自动 / 手动编码、增量解码、稀疏行索引、虚拟表格、原版格式字符、三种搜索范围与字段过滤、副本编辑及安全另存、实时跟随、书签、阅读位置、设置、缓存释放和四个目标的构建打包流程。模块对应 `source`、`archive`、`text`、`format`、`search`、`document`、`save`、`tail`、`settings`、`cache`、`platform`、`worker` 与 `ui`。

原文片段可通过片段副本另存。异常栈折叠、独立长行详情和带来源 / 行号的结构化结果导出尚未实现。异常结束后的孤立临时缓存自动回收尚未实现。

## 功能证据

Release 下 **18 个测试通过**：

- 格式解析与 Unicode 原文位置映射；有效 / 未知控制码、颜色重置。
- 根目录与 `logs/` 范围、越界与更深路径忽略、重复归档成员按物理序号读取。
- 普通日志、gzip、TAR、TAR.GZ、ZIP Stored / Deflate、7z LZMA / LZMA2 的实际样本读取。
- RAR4、RAR5 Stored / compressed 及固实归档最后成员的实际解码。RAR 样本保留上游非日志文件名，验证解码路径；日志名筛选由范围测试验证。
- UTF-8、UTF-16、手动 GB18030、中文、分块与无末尾换行；稀疏索引远距离定位。
- 跨来源搜索、格式码两侧连续命中、正则错误、结果截断与部分失败的区别。
- 保存拒绝覆盖原件 / 硬链接，检测已有目标外部修改，UTF-16 输出与不可表示字符处理。
- 实时追加、截断、轮转、UTF-8 分块、UTF-16 代理对分块，以及书签设置序列化。

实际程序 smoke 读取 25 个受控日志来源，跨目录查询命中 21 行。副本保存与 `latest.log` 测试样本 SHA-256 完全一致。深色、浅色、1,280 × 820 和最小 1,040 × 620 布局均取得窗口自身绘制的截图，包含中文、颜色、搜索结果与编辑标签页。测试模式不读取或写入个人设置。

Clippy `--all-targets -D warnings`、`cargo fmt --check` 与 Git diff 检查通过。每次成功构建后运行 BetterLeaks 1.8.1，覆盖当前工作树源码、脚本、配置和未跟踪新增文件，使用 `--redact --regex-engine stdlib`，本次所有项目扫描退出码为 0。

原生中文输入法、操作系统剪贴板、文件选择器、交互式主题切换和多编辑标签页操作仍需人工验收。窗口 smoke 与核心测试不替代这些结果。

## 大日志测量

`examples/measure.rs` 直接使用生产读取、定位、搜索代码。每行 128 字节，包含中文和 `§` 控制字符；无匹配搜索遍历完整内容。样本先生成于构建目录，操作系统文件缓存未控制，这组结果不代表冷盘或 GUI 首屏速度。Windows 进程工作集在运行中每 20 ms 读取一次系统峰值。

| 指标 | 100 MiB | 1 GiB |
| --- | ---: | ---: |
| 日志行数 | 819,200 | 8,388,608 |
| 首个索引批次 | 1.04 ms | 1.28 ms |
| 完整缓存与索引 | 0.10 s | 1.02 s |
| 1,000 次稀疏定位 | 105.01 ms | 98.25 ms |
| 完整无命中搜索 | 1.00 s | 10.33 s |
| 搜索吞吐 | 99.53 MiB/s | 99.10 MiB/s |
| 核心测量进程峰值工作集 | 5.71 MiB | 5.94 MiB |
| 磁盘解码缓存 | 100 MiB | 1 GiB |

预先取消的读取约 0.04 ms 返回错误。此项验证取消边界，不能代表后台任务正执行解压时的最坏取消时延。表中工作集属于无 GUI 的核心测量进程；完整应用、更多格式和多文档并发的峰值尚未测量。

普通 UTF-8 日志当前也建立 UTF-8 磁盘快照，提供稳定副本与统一索引。1 GiB 是单个缓存的上限，超过上限会明确停止；编辑文档上限 20 MiB，单行上限 32 MiB，总缓存上限 2 GiB。缓存统计不计入发行体积。

## 2026-10-14 连续浏览与目录识别

新增连续日志窗口：按名称或日期排序串联普通日志、压缩日志和归档成员，保留文件分隔与原文行号。滚轮距离在异步读取期间保留，更新视图时维持来源、行号和行内像素偏移。缓存窗口保留可见来源及近邻，离开视野后逐步释放；总磁盘缓存上限调整为 4 GiB，为上一份 / 当前日志和下一份归档的暂存、解码保留空间。

滚动条绘制已修正：FLTK 表格在绘制子滚动条后绘制外框，填充外框会覆盖滚动条，查看器和搜索表格现使用不填充的外框。纵向滚动条始终明确可见，拖动只定位当前文件；滚轮处理先于原生默认处理，负责连续跨文件。复制、片段副本、书签和行号定位均使用实际来源及原始行号；跨文件副本默认 UTF-8。

未提供目录参数时，先识别工作目录自身 / `logs` 子目录，再识别程序目录自身 / `logs` 子目录，最后恢复最近目录。目录参数保留最高优先级。

新增 4 个行为测试后，Release 测试总计 22 个通过。Windows 原生输入脚本另通过 6 个场景：前向跨文件、反向返回、连续越过 gzip 与空文件边界、拖动当前文件滚动条、工作目录为 `logs`、程序置于 `logs`。脚本使用人工日志，仅向本次测试进程发送 Win32 输入消息，已接入 Windows CI。

原生界面测试使用窗口自身截图，核对了文件分隔、原文行号和可见滚动条。Windows EXE 本体约 3.36 MB；最终精确体积由当前发行 manifest 记录。上述跨文件输入与自动目录行为在 Windows 已验证，其他平台由对应构建任务及后续原生输入验收确认。

## 2026-10-14 选取时行消失修复

日志与搜索表格的内层填充背景改为不填充框架，单元格负责自身背景。选取触发局部重绘时，不再先擦除整个内容区域。新增 Windows 离屏像素回归检查，在旧版上复现未选中行被擦除，修复后验证单行 / 多行选取、取消选取、缩放后的选取及搜索结果选取。Windows Release 共 23 个测试通过，连续滚动与目录识别的 6 个原生输入场景再次通过；另以实际鼠标拖选和人工日志截图核对选中区域上下的内容可见。
